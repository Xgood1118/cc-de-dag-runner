在现有 dag 骨架上，把它做成一个支持依赖拓扑与失败恢复的任务编排器。保留现有函数名，只用 Python 标准库，不得引入第三方依赖，不得改动 tasks.json。

## 需要完成

1. **拓扑执行**
   - 按 depends_on 建 DAG 并拓扑排序，依赖全部成功后才执行下游。
   - 检测环并报出环上的全部节点，遇到环要以退出码 2 结束，不能死循环也不能静默跳过。
   - 同一层内互不依赖的任务可以并行执行，并发度可配置，默认 1；并行时输出要按任务 id 归集，不能交叉串行。

2. **失败语义**
   - 任务失败后：它的下游全部标记为 skipped，不允许被执行。
   - 支持 retries 字段：失败后按 1s、2s、4s 退避重试，重试次数用尽才算失败。
   - 与失败任务无依赖关系的分支要继续跑完，不能整体中断。

3. **状态与续跑**
   - 执行状态落 SQLite：run_id、task_id、状态（pending/running/ok/failed/skipped）、尝试次数、开始与结束时间、输出摘要。
   - 支持 --resume：续跑时只执行未成功且依赖已满足的任务，已成功的不重跑。
   - 每次运行要有唯一的 run_id，支持按 run_id 查询历史。

4. **超时与输出**
   - 单任务超时按任务定义，超时视为失败并记 timeout。
   - 结束时输出 JSON 摘要：每个任务的状态、耗时、尝试次数；退出码按是否全部成功决定。

5. **测试**
   - 覆盖：拓扑顺序、环检测、下游 skipped、无关分支继续、重试后成功、超时、resume 不重跑。
   - `python -m pytest tests -q` 全部通过。
